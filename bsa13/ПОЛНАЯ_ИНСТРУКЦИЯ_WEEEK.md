## Обзор платформы Weeek

### Что такое Weeek?
Weeek — это платформа для управления задачами, проектами и командной работой. Она похожа на Trello, Jira или Asana.

### Интерфейс (на основе вашего скриншота)
На вашем скриншоте видно:
- **Левое меню** — навигация между проектами
- **Верхняя панель** — фильтры и настройки вида
- **Основная область** — список задач в виде календаря/списка
- **Задачи** — отображаются как карточки с номером и названием

## Exercise 00 — Выделение типов требований

### Цель
Создать структуру для управления 4 типами требований в Weeek.

### Шаг 1: Создание проекта

1. **Откройте Weeek** — перейдите на https://weeek.net и войдите в аккаунт

2. **Создайте новый проект:**
   - В левом меню найдите кнопку **"+"** рядом с "Проекты" или нажмите на "Проекты"
   - Выберите **"Создать проект"**
   - Название проекта: `BSA13 - Управление требованиями`
   - Описание (опционально): `Проект по управлению требованиями для барбершопа`
   - Нажмите **"Создать"**

### Шаг 2: Создание досок (Kanban) для типов требований

В Weeek задачи организуются на **досках** (как колонки в Trello).

1. **Создайте первую доску:**
   - В проекте нажмите на вкладку **"Доски"** или **"Доска"**
   - Нажмите **"+ Добавить доску"**
   - Название: `Бизнес-требования (BIZ)`
   - Цвет: выберите красный

2. **Повторите для остальных типов:**
   - `Требования пользователей (USR)` — синий цвет
   - `Функциональные требования (FNC)` — зеленый цвет
   - `Нефункциональные требования (NFQ)` — желтый цвет

### Шаг 3: Настройка колонок статусов

Для КАЖДОЙ доски создайте колонки (статусы):

1. **Откройте доску** (например, "Бизнес-требования")

2. **Добавьте колонки** (справа нажмите "+ Добавить колонку"):
   - `Новое` (серый цвет)
   - `На анализе` (синий цвет)
   - `В разработке` (желтый цвет)
   - `На тестировании` (оранжевый цвет)
   - `Включено в патч` (фиолетовый цвет)
   - `Отклонено` (красный цвет)
   - `Отложено` (серый цвет)
   - `Завершено` (зеленый цвет)

### Шаг 4: Создание пользовательских полей (атрибутов)

Это самый важный шаг! Нужно добавить поля для хранения атрибутов требований.

1. **Откройте настройки проекта:**
   - В проекте нажмите на **шестеренку** (⚙️) в правом верхнем углу
   - Выберите **"Поля"** или **"Настройка полей"**

2. **Создайте поля:**

   | Поле | Тип | Описание |
   |------|-----|----------|
   | `ID требования` | Текст | Уникальный идентификатор (BIZ000001) |
   | `Приоритет` | Выпадающий список | High, Medium, Low |
   | `Версия продукта` | Текст | Например: v1.0, v2.0 |
   | `Патч/Спринт` | Текст | Номер спринта |
   | `Источник` | Текст | Ссылка на вышестоящее требование |
   | `Связи` | Текст | ID связанных требований |
   | `Метод проверки` | Текст | Как проверить требование |
   | `Автор` | Пользователь | Кто создал требование |
   | `Дата создания` | Дата | Автоматически |

3. **Как создать поле:**
   - Нажмите **"+ Добавить поле"**
   - Введите название
   - Выберите тип
   - Для "Приоритет" добавьте варианты: High, Medium, Low
   - Нажмите **"Сохранить"**

### Шаг 5: Создание первых требований

Создайте по одному требованию каждого типа для проверки.

1. **Создайте бизнес-требование:**
   - Перейдите на доску "Бизнес-требования (BIZ)"
   - Нажмите **"+ Добавить задачу"** в колонке "Новое"
   - Название: `Повышение посещаемости клиентов`
   - Откройте задачу (кликните)
   - Заполните поля:
     - ID требования: `BIZ000001`
     - Приоритет: `High`
     - Описание: `Снизить количество случаев, когда клиенты забывают о времени записи`
     - Метод проверки: `Процент no-shows до и после внедрения`
   - Нажмите **"Сохранить"**

2. **Создайте требование пользователя:**
   - Доска: "Требования пользователей (USR)"
   - Название: `Информирование менеджером клиентов`
   - ID: `USR000001`
   - Приоритет: `High`
   - Источник: `BIZ000001`
   - Описание: `User Story: Как менеджер, я хочу настраивать расписание напоминаний`

3. **Создайте функциональное требование:**
   - Доска: "Функциональные требования (FNC)"
   - Название: `Настройка расписания напоминаний`
   - ID: `FNC000001`
   - Приоритет: `High`
   - Источник: `USR000001`
   - Связи: `FNC000002`

4. **Создайте нефункциональное требование:**
   - Доска: "Нефункциональные требования (NFQ)"
   - Название: `Производительность отправки`
   - ID: `NFQ000001`
   - Приоритет: `High`
   - Описание: `Время от триггера до отправки не более 1 минуты`

### Шаг 6: Скриншот для ответа

Сделайте скриншот:
- Всех 4 досок
- Или одной доски с созданными требованиями
- Покажите колонки статусов

## Exercise 01 — Создание требований

### Цель
Создать полный набор требований для функции "Автоматические напоминания".

### Контекст
Выделенное предложение из задачи:
> "Система должна обеспечивать автоматическую отправку напоминаний клиентам через выбранный клиентом канал связи (Telegram, WhatsApp, VK, СМС) по настроенному менеджером расписанию."

### Шаг 1: Создайте User Stories (USR)

В доске "Требования пользователей" создайте 4 задачи:

#### USR000001: Информирование менеджером
- **Название:** Информирование менеджером клиентов о записи
- **Описание (User Story):**
  ```
  Как: менеджер барбершопа
  Я хочу: настраивать расписание автоматических напоминаний
  Чтобы: клиенты не забывали о записи
  ```
- **Критерии приемки:**
  - Менеджер может задать время отправки
  - Менеджер может выбрать каналы связи
  - Менеджер может просмотреть статус отправки
- **ID требования:** USR000001
- **Приоритет:** High
- **Источник:** BIZ000001
- **Связи:** USR000002, FNC000001

#### USR000002: Получение клиентом напоминания
- **Название:** Получение клиентом напоминания о записи
- **User Story:**
  ```
  Как: клиент барбершопа
  Я хочу: получать напоминание о предстоящей записи
  Чтобы: не забыть о визите
  ```
- **ID:** USR000002
- **Приоритет:** High
- **Источник:** BIZ000001
- **Связи:** USR000001, FNC000002

#### USR000003: Взаимодействие по каналам связи
- **Название:** Взаимодействие по каналам связи
- **User Story:**
  ```
  Как: клиент
  Я хочу: выбирать удобный канал связи
  Чтобы: получать уведомления там, где я чаще бываю
  ```
- **ID:** USR000003
- **Приоритет:** Medium
- **Источник:** USR000002
- **Связи:** FNC000003

#### USR000004: Настройка расписания информирования
- **Название:** Настройка расписания информирования
- **User Story:**
  ```
  Как: менеджер
  Я хочу: гибко настраивать время отправки
  Чтобы: адаптировать под разные услуги
  ```
- **ID:** USR000004
- **Приоритет:** Medium
- **Источник:** USR000001
- **Связи:** FNC000001

### Шаг 2: Создайте функциональные требования (FNC)

#### FNC000001: Настройка расписания
- **Название:** Настройка расписания отправки напоминаний
- **Описание:** Система позволяет менеджеру настраивать время и условия отправки
- **Функциональность:**
  - Создание правила (услуга, время, каналы)
  - Редактирование правила
  - Удаление правила
  - Просмотр списка правил
- **ID:** FNC000001
- **Приоритет:** High
- **Источник:** USR000001, USR000004
- **Связи:** FNC000002, FNC000003

#### FNC000002: Автоматическая отправка
- **Название:** Автоматическая отправка напоминаний
- **Описание:** Система автоматически отправляет напоминания по расписанию
- **Функциональность:**
  - Проверка расписания каждые 15 минут
  - Формирование списка клиентов
  - Отправка через выбранный канал
  - Логирование отправки
- **ID:** FNC000002
- **Приоритет:** High
- **Источник:** USR000002
- **Связи:** FNC000001, FNC000003

#### FNC000003: Управление каналами связи
- **Название:** Управление каналами связи клиента
- **Описание:** Система хранит предпочтения клиентов по каналам связи
- **ID:** FNC000003
- **Приоритет:** Medium
- **Источник:** USR000003
- **Связи:** FNC000002

### Шаг 3: Создайте требования к интерфейсам

В Weeek можно создать отдельную доску "Интерфейсы (INT)" или добавить в описание FNC.

#### INT000001: Интерфейс настройки расписания
- **Название:** Интерфейс настройки расписания напоминаний

## Exercise 02 — Позитивный тест-кейс

### Цель
Создать позитивный тест-кейс для UC02 (настройка расписания напоминаний).

### Что нужно сделать

1. **Файл тест-кейса уже создан:** `ex02/positive_test_case.xlsx`

2. **Разместите в облачном хранилище:**
   - Загрузите файл в Google Диск, Яндекс.Диск или Dropbox
   - Откройте доступ по ссылке
   - Скопируйте ссылку

   - Создайте новую доску "Тестирование" (если нет)
   - Нажмите "+ Добавить задачу"
   - Название: `[TC-POS-001] Успешная настройка расписания напоминаний`
   - Описание:
     ```
     Позитивный тест-кейс для FNC000001
     
     Цель: Проверить успешное создание правила напоминания
     
     Ссылка на тест-кейс: [вставьте ссылку на Excel файл]
     
     ID: TC-POS-001
     Приоритет: High
     Тип: Позитивный
     ```
   - Установите метки: `test-case`, `positive`, `high-priority`
   - Назначьте исполнителя (если есть тестировщик)

### Структура тест-кейса (кратко)

| Элемент | Описание |
|---------|----------|
| ID | TC-POS-001 |
| Название | Успешная настройка расписания напоминаний менеджером |
| Приоритет | High |
| Предусловия | Менеджер авторизован, услуга существует |
| Шаги | 10 шагов (выбор услуги, времени, каналов, сохранение) |
| Ожидаемый результат | Правило создано и отображается в таблице |

## Exercise 04 — Оценка результата

### Цель
Оценить результаты тестирования и создать отчеты о дефектах.

### Шаг 1: Заполните фактический результат в тест-кейсах

В Excel-файлах заполните:
- Дата выполнения
- Исполнитель
- Результат: Пройден / Не пройден
- Комментарий

### Шаг 2: Создайте отчеты о дефектах

Если тест не пройден — создайте задачу-дефект в Weeek.

#### Пример создания дефекта DEF-001:

1. Создайте доску "Дефекты" (если нет)

2. Создайте задачу:
   - **Название:** `[DEF-001] Некорректная привязка бронирования к клиенту`
   - **Описание:**
     ```
     Краткое описание: Система отображает неверного клиента при просмотре забронированного слота
     
     Шаги воспроизведения:
     1. Открыть расписание мастера на 25.03.2026
     2. Найти слот 14:00
     3. Открыть детали слота
     
     Ожидаемый результат: Клиент: Иванов И.И.
     Фактический результат: Клиент: Петров П.П. (неверный клиент)
     
     Окружение:
     - ОС: Windows 11
     - Браузер: Chrome 122.0
     - Разрешение: 1920x1080
     ```
   - **Тип:** Баг / Дефект
   - **Приоритет:** Critical
   - **Важность:** High
   - **Метки:** `bug`, `critical`, `booking`
   - **Связанные задачи:** Укажите TC-POS-001

3. **Прикрепите файлы:**
   - Скриншоты
   - Логи

### Шаг 3: Заполните ФР в тест-кейсах

В задаче тест-кейса в Weeek добавьте комментарий:
```
Фактический результат: Не пройден
Дефект: DEF-001
Дата: 20.03.2026
```

Или если пройден:
```
Фактический результат: Пройден
Дата: 20.03.2026
```

## Полезные советы по Weeek

### Горячие клавиши
- `N` — создать новую задачу
- `M` — назначить исполнителя
- `L` — установить метку
- `D` — установить дедлайн

### Фильтрация
- Используйте фильтры в верхней панели для поиска задач
- Можно фильтровать по исполнителю, метке, приоритету

### Представления
- **Список** — удобно для просмотра всех задач
- **Доска (Kanban)** — наглядно для статусов
- **Календарь** — для планирования по датам

### Экспорт
- Можно экспортировать задачи в CSV/Excel
- Полезно для создания отчетов
